# 已知限制与后续扩展点

> 这份清单是「诚实账本」。写清楚哪些做不到、为什么不做、以后怎么补，
> 比在 UI 里假装支持要好。每条都尽量给出根因，而不是一句「暂不支持」。

## 一、导出

| 限制 | 现状 | 根因 | 后续 |
| --- | --- | --- | --- |
| 只支持 WebM（VP9/VP8），没有 MP4 | `exportWebm()` 用 `MediaRecorder` | 浏览器原生编码器里 H.264 的可用性依赖平台与许可证，不能保证 | 用 WebCodecs `VideoEncoder` + mp4 muxer，或 ffmpeg.wasm 转码 |
| 没有 GIF | — | GIF 调色板 + 抖动需要额外编码器，体积也大 | 引入 gif.js 之类的工作线程编码器 |
| ~~没有音轨~~ | **v2.9 已支持**：`AudioLayer` + WebM 混流（Opus） | 见 docs/09-audio.md | 音频**文件**导入仍未支持，音源是参数化合成的 |
| ~~没有字幕~~ | **v2.15 已支持**：SRT / WebVTT 双向（`export.subtitles`） | 见 docs/15-deliver.md | 逐字时间是按字符权重切的，不是听出来的 |
| ~~只能导出整片~~ | **v2.15 已支持**：`Project.range` 出片区间，四个出口共用 | 见 docs/15-deliver.md | — |
| ~~导出时长会漂~~ | **v2.15 已修**：对齐绝对时间格，渲染跟不上就丢帧 | 旧实现「推一帧 sleep 一帧」，误差累积 | 更彻底的做法是 WebCodecs 自己写 PTS |
| 剪辑表只有 EDL，没有 FCPXML | `export.edl` 出 CMX 3600 | 本工程没有「素材库 + 源路径」，FCPXML 写出来全是离线素材 | 真要 FCPXML 得先有「素材库」这一层概念 |
| HTML 代码层导出依赖 SVG `foreignObject` 栅格化 | `rasterizeHtml()` | 浏览器安全策略：外链 CSS/字体/图片可能不加载，部分滤镜不支持 | 引导用户把样式内联；长期可换成 OffscreenCanvas + 自绘 |

## 二、代码层沙箱

- **不是安全沙箱**。用 `new Function` + shadow 掉常见全局（`window`、`document`、`fetch`、`localStorage` 等），
  能挡住「误用」，挡不住「刻意逃逸」。它的定位是「防止创作者写错代码把编辑器搞崩」，
  **不要用它运行来路不明的代码**。
- **GLSL 引擎**只做了基础的 uniform（`u_time` / `u_resolution`），没有多 pass、没有纹理输入。
- **熔断是启发式的**：连续 3 次异常就停掉该层，错误修好后需要重新触发一次渲染（改代码/重载）才恢复。
- **无法打断死循环**：`while(true)` 会卡住主线程。真正的解法是把代码层放进 Worker + OffscreenCanvas，
  这需要重写渲染管线（因为 `renderScene` 目前在主线程按 z 序合成）。

## 三、多窗口

- **降级链**：`window.open` 弹窗 → Document Picture-in-Picture → 应用内浮动面板。
  - 弹窗可能被浏览器拦截（非用户手势触发时）；
  - PiP 仅 Chrome/Edge 116+ 支持；
  - 浮动面板在同一页面内，**不是真正的独立窗口**（切换标签页会一起隐藏）。
- **同一时间只允许一个 Host**：新开的编辑器标签页不会自动变成镜像，需要手动在图层行点「独立窗口」。
- **镜像窗口只读**：可以改少量属性，但所有修改都发命令回 Host 等结果；断线时会显示「已断开，等待重连」。
- **视频层在镜像里可能轻微不同步**：Host 每 100ms 广播一次播放头，Client 做线性外推；
  网络/线程抖动时最多差 1~2 帧，导出不受影响（导出在 Host 内完成）。
- **不跨设备**：`BroadcastChannel` 只在同源同浏览器内生效。

## 四、AI 与 Agent

- **只支持 OpenAI 兼容的 `/chat/completions` + function calling**，没有适配 Anthropic Messages / Gemini 原生协议。
- **没有流式输出**：一次请求一次响应，长任务看起来像「卡住」。演示模式（无 Key）是本地规则匹配，能力有限。
- **没有多轮自动纠错**：模型给出非法参数时，错误会回给模型一次，但只重试一轮。
- **API Key 的加密是「本地混淆」级别**：AES-GCM 加密后存 IndexedDB，密钥材料也在 IndexedDB 里。
  它能防止「随手翻 localStorage 就看到明文」，**不能防止本机上已经能跑脚本的攻击者**。
- **MCP 通道要求本机跑两个进程**（bridge + mcp），且 bridge 的令牌存在 `agent-bridge/.token` 明文里。
  这是本地开发工具的常规取舍；真要更强，就得引入系统钥匙串。
- **桥接不鉴权来源**：任何本机进程拿到令牌就能改海报。令牌是防线，不是权限系统。

## 五、编辑器能力

- **没有曲线编辑器**：关键帧有（v2），缓动支持预设名与 `cubic-bezier` 数值，但没有可视化曲线拖拽面板。
- **没有图层组 / 遮罩 / 蒙版**：z 序就是数组顺序，够用但表达力有限。
- **快捷键不可自定义**：J/K/L、I/O、`,`/`.`、M 是写死在 `EditorApp` 里的。
  openfilm 与 FreeCut 都有热键编辑器，Kinelayer 暂时没有 —— 原因是命令层已经是唯一入口，
  真要做的话应该是「快捷键 → 命令类型 + payload」的一张表，而不是往事件处理里加分支。
- **倒放没有声音**：`J` 让播放头倒着走，但音频图不能倒跑（会变成刺啦一声），所以自动静音。
- **文本排版是简化实现**：手工断行（CJK 按字、拉丁按词）+ `letterSpacing`，
  没有连字、没有双向文本（RTL）、没有富文本段落级样式。
- **撤销栈上限 120 步**，连续拖动会在 700ms 内合并成一步；合并策略是「同类型 + 同图层 id」。
- **没有协作、没有云端存储**：自动保存写 IndexedDB，清浏览器数据就没了。
  备份手段有两种：`.kly` 工程包（含素材，换机器能直接打开）与 JSON 备份（纯文本，适合进 git）。
- **JSON 备份不含图片/视频二进制**：资源留在 IndexedDB 里。要连素材一起带走，用 `.kly` 工程包，
  否则换机器打开 JSON 会看到「资源缺失」占位，需要重新导入素材。
- **工程包有硬上限**：单文件 64MB、总计 384MB、条目 400 个。更大的工程（比如带 4K 视频）
  目前打不进去，得先把素材压小 —— 这是为了避免打开包时把浏览器内存吃穿。
- **触屏/手写笔未适配**：舞台交互基于 Pointer Events 的鼠标语义（中键平移、Ctrl+滚轮缩放），
  触屏上只能点选，不能双指缩放。

### 自定义命令（v2.7）

- **没有条件与循环**：宏是「一串命令按顺序跑」，不是编程语言。要分支就在定义时拆成两条宏。
- **宏不能调宏**：会引入递归与深度限制，收益小于成本。
- **不跨设备、不进工程包**：宏存在本机独立的 IndexedDB store 里（跟人不跟工程），
  换浏览器或清数据就没了；导出能力目前只有 `custom.list`（返回完整 JSON，可复制粘贴）。
- **命令描述只有中文**：注册表里 109 条命令的 `description` 没有英文版，命令面板与
  自定义命令编辑器都会原样显示。属于全局未翻译项，不是某一处漏翻。

## 五之二、导入（v2.5 阶段 A / B）

- **Remotion 工程是「静态解析」，不是「还原原片」**。只认结构（JSX 元素、字面量、常量表、
  interpolate/spring 的参数），不还原运行时：`useContext` 里的数据、`fetch` 的返回、
  循环里算出来的坐标一律不猜。拆不出来的组件整块留成 `remotion-component` 代码层。
  细节见 [04-code-video-integration.md](./04-code-video-integration.md)。
- **`remotion-component` 层不可内部编辑**：时间轴不展开它的内部关键帧，双击是**只读**源码查看器；
  容器上的 x/y/opacity 仍可打点（那是图层属性，不是组件内部）。成片必须外部 `npx remotion render`。
- **spring 只是近似**：不跑物理积分，压成 eased 0→1 两个关键帧，报告里会明说。
  `scale` 动画没有对应轨道（Kinelayer 用 width/height 表达缩放），导入时跳过并记说明。
- **remotion-kit 不一定含原工程整树**：源码总量超过 600KB 时只保存解析出来的组件，
  报告里会说「kit 只能导出解析出来的组件」。kit 的「能出片」本机只在结构层验证过
  （语法合法 / import 路径存在 / README 命令正确），真跑 render 需要用户自己在 Node 环境执行。
- **形状没有原生图层类型**：矩形/圆/路径在导入时生成 canvas2d 代码层（位置、尺寸、透明度能打关键帧，
  内部不能逐元素编辑）。Remotion 里带背景的容器（含 `AbsoluteFill`）同理。
- **`scene.ai.json` 不含二进制**：导回来后媒体层只剩资源名，需要重新指定图片/视频。这是设计取舍 ——
  语义层要塞进 Agent 的上下文预算，base64 会让它失效。要连素材一起搬，用 `.kly`。
- **场景 JSON 的识别靠启发式**：时间单位先看 `timeUnit`，没有就按「数值 ≤120 当秒、否则当毫秒」推断；
  图层类型看 `type/kind/elementType`。认不出的字段不会报错，只会出现在降级说明里。
- **关键帧时间单位靠图层时长反推**：超出图层时长的按绝对时间处理并减去 inPoint，其余按相对时间。
  极端情况（图层比整条时间轴还长）可能判错，报告里的轨道/关键帧计数可以用来核对。
- **导入不合并资源**：每次导入都新建一条工程记录与新资源，不做跨工程去重。
- **预检是 async 的**（v2.5b 起）：Remotion 分支要动态加载 `@babel/parser`。不读写库这条没变。
- **HTML 只拆绝对定位的元素**（v2.5c）：`position:absolute|fixed` 且写了 `left/top` 的才认。
  flex / grid / 普通流里的位置取决于字体度量与浏览器排版，静态算不出来 —— 硬算的结果是
  「看着差不多、改起来全是错」。这类元素整块留成 html 代码层，报告里写明数量。
  想提高提取率，让 AI 生成时用绝对定位写死坐标。
- **HTML 的 CSS 只读声明块**，不实现 specificity / `!important` / 继承。合并规则是
  「文档顺序覆盖 + inline style 最高」。样式写得越平（少嵌套、少 `!important`）提取越准。
- **sandbox iframe 的白底去不掉**：Chrome 里 `html,body{background:transparent}` 也没用
  （默认 / 文档透明 / 文档透明 + 元素透明 / 加 `color-scheme`，四个变体实测全是白的）。
  所以 html 代码层的背景被强制成画布底色，并收缩到内容包围盒 —— 它仍会挡住自己那一小块下面的内容。
- **HTML 里的远程依赖不拦**：`<script src="https://cdn...">` 会真的被 iframe 加载。
  这不是应用发起的请求，但你导入的页面会发起。导入报告会列出来，`origin.external` 也记着。

## 六、性能与兼容

- `renderScene()` 每帧整张重绘（含代码层求值）。1080×1440、7 个图层在 30fps 下很轻松；
  但如果叠十几层 4K 图片 + 多个 GLSL 层，帧率会掉。目前没有脏矩形优化。
- **代码层的耗时只由两个量决定：像素数 × 每像素计算量**。所以才有了
  `CodeSpec.renderScale`（0.25–1，默认 1）：低频成片的画面（噪声场、雾、辉光）把它降下来，
  像素数按平方减少；文字与细线不要降，放大后会糊。
  一支 64 秒九层样片在这条规则下的实测账见 [10-performance.md](10-performance.md) ——
  p95 从 155ms 压到 20.5ms，全片 320 个采样点无一超出 30fps 预算。
  需要注意这是**软件光栅化**（无 GPU）下的数字；有显卡时 WebGL 那一段会低一到两个数量级。
- **`motionBlur` 花的是绘制次数，不是像素。** 它和 `renderScale` 是两条独立的杠杆：
  `samples: 5` 就是同一层画五遍再平均，耗时长约 5 倍（仅那一层）；`renderScale: 0.5` 则是把
  像素砍到四分之一。两者可以叠加，但要乘起来算。一帧的预算只有 33.3ms，所以它只适合
  用在**一两层**需要方向感的元素上（落版叠字、甩入的标题），不要给整片每一层都开。
- **`shutter` 是一帧曝光，不是重影次数。** 30fps 下一帧 33.3ms，给 110ms 会得到三次离散重影
  （长曝光效果），给 44ms 才是真正的运动模糊。
- **速度网格是全局恒定的。** `project.tempo` 只有一个 bpm，没有变速曲线（accelerando、
  半拍切换都没建模）。`meter` 只影响强拍位置，表达不了 7/8 里的 3+2+2 细分。
- **逐字时间不是从人声测出来的。** 本工程的音轨是合成的，所以词级时间是「行区间按字符权重切」。
  接了真人声需要先做 forced alignment 再写进 `project.lyrics` —— 数据结构够用，对齐工具没做。
- **`u_resolution` 的语义容易写错**：它必须是**绘图缓冲区**的像素尺寸，不是图层设计尺寸。
  两者在 `renderScale = 1` 时相等，所以这个错误只在降分辨率的那一层上暴露，而且只在
  以画面中心为原点的效果上暴露（噪声看不出来，放射状画面一眼穿帮）。见 [11-score.md](11-score.md)。
- **示例演示不了「外部资源」这条路。** 两支示例都是零外部资源的，所以**图片层、视频层、
  HTML 层、Remotion 组件层**在示例里看不到 —— 那不是没做，是「零外部资源」这条约束的代价。
  这四种层各自的入口：资源面板上传 / 导入 `.kly` 工程包 / 拖入 HTML 片段 / 导入 Remotion 工程，
  说明分别在 [06-after-import.md](06-after-import.md) 与 [04-code-video-integration.md](04-code-video-integration.md)。
- 舞台的 HTML 代码层用 `<iframe>` 叠加预览，滚动/缩放时靠 CSS transform 跟随，极端缩放下可能有 1px 抖动。
- 推荐 Chrome / Edge 116+。Safari 缺 `documentPictureInPicture`、`navigator.fonts`，
  且 `ctx.letterSpacing` 支持较晚，字距会退化。
- 首屏按视图分包：启动页约 204KB gzip（共享运行时 178KB + 启动页 13KB + 公共组件 3KB + CSS 8KB + HTML 1KB），
  进编辑器再加载约 215KB（CodeMirror、渲染引擎、AI 面板都在这里）。图层窗口是独立 chunk（~5KB）。
  共享运行时里包含导入管线与 `scene.ai.json` 的投影逻辑 —— 它们是命令层的依赖，两个视图都要用。
- 示例样片的九段画面源码是**单独一个 chunk**（42KB / 17KB gzip），`createSampleProject()` 走
  `await import('./showcase/film')`：一个只想打开启动页的人不该为「一份可能永远不会被创建的示例」
  付这份下载，而真要创建示例时每个浏览器只会拉一次。拆出来之后共享运行时从 195KB 降到 178KB gzip。
- `@babel/parser` 单独一个 chunk（289KB / 73KB gzip），**只在真的导入 Remotion 工程或带 `<script>` 的 HTML 时才下载**（两条路共用同一个 chunk）。
- html 代码层的 iframe 会在导入后异步量一次内容包围盒（量到之前 `opacity: 0`），
  所以导入瞬间那一层是空的，几十毫秒后才出现。不用「先显示后跳位」是刻意的 —— 跳位更刺眼。
  这不是优化洁癖：把 babel 塞进共享 chunk 会让启动页白背 73KB，而 99% 的会话不会导入 Remotion。

## 七、后续扩展点（按「投入产出比」排序）

1. **导出预设**：把「尺寸 + 时长 + 帧率 + 文件名模板」存成预设，一条命令 `export.preset` 就能批量出图。
2. **关键帧曲线**：在现有 `LayerAnimation` 旁边加 `tracks`，不动命令总线，只扩数据与采样函数。
3. **代码层 Worker 化**：解决死循环与主线程卡顿，顺带让 GLSL 多 pass 成为可能。
4. **命令包（插件）**：`registerCommands()` 已经是纯函数式注册，外部可以按「包」注入自己的命令，
   UI 的「命令」面板会自动出现——这是本项目最容易被低估的扩展点。
5. **MP4 / GIF 导出**：WebCodecs + muxer，或 ffmpeg.wasm。
6. **模板市场**：一个模板 = 一份 `Project` JSON + 资源清单，`project.load` 已经能直接吃。
7. **多人协作**：真要做的話，先解决「谁持有撤销栈」，再谈 CRDT；否则会同时失去单权威模型和可预测的撤销。
