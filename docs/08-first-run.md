# 第一次打开：示例样片、介绍动画与音频

一个空的工作台会让新用户卡在第一个问题上：**这玩意儿能做什么？**

所以第一次打开时，工程库里已经躺着一支 **64 秒的极限样片** —— 八段、九层代码、
零外部资源，把引擎能画的东西走一遍：巨号标题、等轴城市、HUD 锁定、GLSL 液态、
滚动源码、视差纹理墙。介绍页上另有一段四拍动画，把「画布 → 图层 → 关键帧 → 命令」
走一遍。这一篇讲这两件事怎么落地、以及为什么要这么落；音频层单独有一篇
（[09-audio.md](09-audio.md)），性能账单独有一篇（[10-performance.md](10-performance.md)）。

---

## 一、时序：谁在什么时候做

```
启动 → 路由 `/` → Launcher 挂载 → refresh()
                                    ├─ project.seedSample   ← 幂等：只写库，不动当前文档
                                    └─ project.listRecent   ← 读索引，渲染卡片
```

关键点：**塞示例是一个命令，不是 Launcher 直接写 IndexedDB**。

`Launcher` 的注释里写着「这里不碰 IndexedDB，也不改 store 里的 project」。这条规矩
在加示例时同样要守：所有写操作回命令总线，Launcher 只负责发命令与渲染。
好处是同一个动作在三种入口（页面、覆盖层、AI）里行为一致，且能在审计里看到。

`refresh()` 每次打开都会调 `project.seedSample`。这不会带来额外开销 ——
除了第一次，它都是一次 prefs 读就返回（见第四节）。

---

## 二、为什么不自动打开它

「自动加载并展示」有两种解法：自动跳进编辑器，或者放进工程库等用户点。

选了后者，理由是**第一屏该是可选的**：

| 自动打开 | 放进工程库 |
| --- | --- |
| 用户还没理解这是什么，就被塞进一个陌生画布 | 先看到工程库，知道「这里是我的东西」 |
| 想新建就得先关掉示例、再回来 | 想新建直接点左边 |
| 示例被编辑后，下次打开还是它 | 示例只是列表里的一条，随时可开可删 |

所以「自动加载」落在**数据层**（库里有这条记录），「展示」落在**列表层**（卡片 + 引导条），
不越界到导航层。

## 三、这支片子长什么样

1920×1080 / 30fps / 64 秒，八段（第五段带一层字幕，所以是 9 个代码层）：

| 段 | 时间 | 画面 |
| --- | --- | --- |
| 01 冷开 | 0–8.8s | 巨号 `15` 砸下来、扫光过、15 格逐个点亮 |
| 02 点名 | 8.8–16.8s | 十五个 MG 风格名，500ms 一拍，竖带切过去 |
| 03 等轴城市 | 16.8–24.8s | 13×13 格子按到中心的距离错峰长出高楼 |
| 04 HUD 锁定 | 24.8–32.8s | 角括号收拢、三环刻度咬合、锁住一只线框目标 |
| 05 液态 | 32.8–40.8s | GLSL 三级域扭曲噪声场，上面压大字标 |
| 06 技术账 | 40.8–48.8s | 滚动源码 + 三个数字 + 底部波形 |
| 07 风格墙 | 48.8–56.8s | 五列视差纹理墙，巨字穿镜 |
| 08 落版 | 56.8–64s | 标志 / 标题 / 署名 / 淡出 |

**一段 = 一个覆盖整段的代码层**，图层名就是分镜表（`03 · 等轴城市`、`07 · 风格墙`）。
代码层拿到的是**全片毫秒**，所以每段源码里自己写着 `const START = 16800`，
换章节不用重新对表 —— 时间轴上删掉一段、把相邻两层拉长，片子就重排了。

这不是「用关键帧堆出来的片」，全片 **0 条关键帧轨道**：动画全部写在
`src/core/showcase/scenes.ts` 的九段源码里，改内容就是改那九个字符串。

性能上有一处刻意的取舍：`05 · 液态 shader` 是整片唯一的逐像素画面，
标了 `renderScale: 0.5`（内部分辨率减半再放大）。为什么只降它、为什么是 0.5，
以及不降的话会慢多少，见 [10-performance.md](10-performance.md)。

## 四、示例工程的四条约束

`src/core/sampleProject.ts` 里的注释写了详细理由，这里只列结论：

### 1. 零外部资源

没有图片、没有视频、没有音频文件、不用本地字体。否则第一次打开就是一片「资源缺失」的灰块 ——
示例会变成故障演示。自检里有一条 `不依赖任何外部资源：assets === 0` 守着它。
画面全是文本层 + canvas2d 代码层，声音是 WebAudio 现场合成（见 09-audio.md）。

### 2. 第 0 帧就有内容

这是最容易翻车的一条。演示工程的图层带着入场预设（`enter`），而入场动画在 t=0 的透明度是 0，
照搬的话新用户打开只看到背景，还得先按空格才知道有东西。

打开工程时 `playhead` 恒为 0，所以示例**不用入场/退场预设**（全片 `enter` / `exit` 都是空的）。
`01 · 冷开` 从 0ms 起就在画：底色径向渐变 + 60px 细网格在第一帧就是实的，
巨号 `15` 在 200ms 内砸下来 —— 那一帧它不是空的，只是动画刚开始。

顺带解决了缩略图：`makeThumbnail` 在 t=0 渲染，有入场动画的话卡片上会是一张空图。
这条片子的第 0 帧本来就接近全黑，所以自检没有用「字节数够大」这种阈值去判，
而是把缩略图解码成 64×36 数颜色（≥24 种才算「是真的画面」）。

### 3. 看得出能改

- 图层面板就是分镜表：`01 · 冷开 · 15` … `08 · 落版`，一眼看出哪层是第几段
- 每段只占一层，改画面＝改那一层的源码；删一层就是删一段，时间轴自己接上
- 全片 0 条关键帧轨道 —— 这不是缺点，是这一版故意的：它证明「动画全写在代码里」
  也能撑起一支成片，而不只是一堆会动的色块

### 4. 声音必须真的响

六条音轨（四条铺底按段落换和弦 Am → F → C → G、一条 120BPM 节拍、一条钉在切点上的提示音）
不能只是数据好看。自检里有一条会走 `OfflineAudioContext` 把整条音轨算一遍，
`peak > 0.01 && rms > 0.001` 才算过 —— 这样「静音失败」这种问题不会等到用户戴耳机才发现。
实测 `peak 0.057 / rms 0.0053`，长度 64000ms 与工程时长对齐。

## 五、幂等：三个判据，一个版本号

```ts
const seeded = await seededSampleVersion();              // 0 / 1 / n
const existing = await getProjectMeta(SAMPLE_PROJECT_ID);
if (!force && seeded >= SAMPLE_VERSION) return { created: false, reason: 'seeded' };
```

| 判据 | 挡住什么 |
| --- | --- |
| prefs 里的 `sampleVersion` | 同一版本塞过就一次读结束，不碰工程本体 |
| 固定 id `prj_sample_start` | 标记丢了但工程还在（手动清过 prefs、标记那次写失败） |
| `existing.updatedAt > existing.createdAt` | 用户改过它 —— 那就不能再盖 |
| 当前文档 id（`draft.id`） | 示例正开在编辑器里：覆盖会和自动保存打架，会把旧内容写回来 |

### 5.1 为什么要版本号（这一条是踩出来的）

v2.8 的示例是 4 秒海报「示例 · 从这里开始」，v2.9 换成了 96 秒六章导览，v2.10 又换成了 64 秒九段样片。
只记「塞过没有」的后果是：**所有跑过 v2.8 的浏览器永远停在旧海报上**，
而且界面上完全看不出来 —— 用户只会觉得「说好的示例呢」。

所以 `SAMPLE_VERSION` 是硬约定：**换内容必须 +1**。判据从「塞过没有」变成
「塞的是第几版」。prefs 里只有 v2.8 写下的 `sampleSeeded: true`（没有版本号）
时按第 1 版算，不做数据迁移。

### 5.2 换新的三条分支

| 情况 | 做什么 | 界面说 |
| --- | --- | --- |
| 旧版，没被动过 | 原地换新（同一个 id，卡片位置与「当前」标记都不变） | 「示例已换成新版：64 秒 · 16 层 · 6 条音轨」 |
| 旧版，但被改过 | **不覆盖**，也先不写版本标记 | 「示例有新版…你在这份上改过东西，所以没动它」+「换成新版」 |
| 用户早就删了 | 只把版本标记跟上 | 什么都不说（承诺过「删掉就不会再出现」） |

第一条之所以敢直接换，是因为自动保存只在 `project.version` 变化时才写库 ——
「打开看过但没改」的 `updatedAt` 仍然等于 `createdAt`，可以判定为没动过。

第二条不写版本标记是故意的：写了之后下次刷新连这句提示都不会再出现，
用户就真的再也见不到新版了。按钮走 `force: true`，覆盖前还会 `confirm` 一次。

第三条的判据不能是 `lastProjectId`：启动页（page 形态）内存里是一份空工程，
用「上次打开的 id」会把「上次刚好看过示例」的人永远卡在旧版上。
读 `draft.id` 才是「示例此刻真的开着」。

**记的是「已经塞过」，不是「用户没见过」。** 用户第一件事可能就是把它删掉 ——
那就该真的没了，而不是下次刷新又冒出来。

但删掉之后总得有条路放回来，所以空状态里有一个「放回示例工程」按钮，
走的是 `project.seedSample { force: true }`。`force` 存在就是为了这条后路。

### 为什么示例的 `version` 保持 1

`flushCurrent()` 里有一条：`version <= 1` 的工程切走时不落盘 —— 那是给「启动时内存里
那份演示工程」用的，否则每次刷新都会往库里塞一条新记录。

示例是**已经开始归档的记录**，不依赖这条豁免；保持 `version: 1` 只是表明
「建出来之后还没被任何命令改过」。用户打开它之后，`project.open` 会把它写成
`draft.version + 1`，之后自动保存就正常工作了。

## 六、介绍页那段动画

`src/ui/IntroDemo.tsx`，四拍循环，每拍 2.2 秒：

| 拍 | 画面 | 讲什么 |
| --- | --- | --- |
| 01 画布 | 舞台点亮，标题浮现 | 尺寸 · 时长 · 帧率 |
| 02 图层 | 标题框选中，图层面板对应行亮起 | 位置 · 样式 · 叠放 |
| 03 关键帧 | 播放头从左扫到右，菱形亮起，标题上抬、光斑放大 | 轨道 + 播放头求值 |
| 04 命令 | 命令行打字机式打出 `layer.create {...}`，画布上多一条 | 同一条命令总线 |

### 为什么不用 canvas 真渲染一套

介绍页要讲清楚的是**界面语言**（怎么选、怎么改、怎么打点），不是渲染效果。
用界面本身去画界面最直白；再挂一条渲染管线既慢，又等于在介绍「渲染」而不是「怎么用」。

真正的渲染能力由旁边的示例卡片承担 —— 那张缩略图就是渲染器的产物。

### 缩放：固定设计稿 + 等比缩放

内部是「百分比定位 + 固定像素细节」的混排。直接把容器拉大，方块会变长、字号不变，
比例全乱。所以先按 380×210 画一张，再用 `ResizeObserver` 量容器宽度做 `scale()`：

```tsx
const fit = () => setScale(el.clientWidth / DESIGN_W);
```

任何宽度下比例一致，窄屏也不会挤压。

### prefers-reduced-motion

检测到用户要求减少动态时，**停在第三拍**（信息量最大的一帧）且不循环。
这不是「关掉动画」，是「给一个静态但完整的说明图」。

## 七、故意没做的

- **自动跳进编辑器**：见第二节，第一屏该是可选的。
- **示例跟工程包一起走**：不进 `.kly`。它是本机的引导素材，不是用户数据。
- **多个示例 / 模板市场**：一个够了。要更多模板是另一个产品决策（分类、预览、来源标注）。
- **动画做成视频**：一段 20KB 的 CSS/SVG 比 2MB 的 mp4 更省，也不会有首帧黑屏。
- **给示例配一条音轨就完事**：那样「音频」只是个数据字段。这里做成了可用的图层类型 ——
  能新建、能调音量/淡入淡出、时间轴上有波形、导出会混进 WebM。
- **把动画做成可交互**：介绍页的职责是「说明」，交互留给示例工程本身。

## 八、自检

`scripts/sample-check.mjs`，40 项，九个区块：

| 区块 | 验什么 |
| --- | --- |
| 首屏 | 一条示例、缩略图非空、带「示例」徽标、引导条说出时长与音轨数 |
| 介绍动画 | 四拍齐全、相位会自己推进、指示器跟着走 |
| 减少动态 | `prefers-reduced-motion: reduce` 下停在第三拍且不动 |
| 幂等 | 刷新不重复创建、引导条只出现一次 |
| 打开它 | 64 秒 / 16 层 / 9 个代码层 / 八段标题齐全 / 0 轨道 / 0 资源 / 无入场预设 / 只有液态那层是半分辨率 |
| 声音 | 离线渲染 peak 非零、时长 64s 对齐、第 30 秒同时响 pad 与 pulse、波形有包络 |
| 删除 | 删完清空、刷新不复活、空状态能一键放回 |
| 版本升级 | 把 meta 改回 v2.8 的样子（老名字 / 4 秒 / 无版本号）再刷新：没被动过就换新并说明、被改过就保留并给出「换成新版」、点了才换、版本标记落盘 |
| 双语 | 英文模式下介绍区零中文、四拍标签也翻译了 |

版本升级那一块只改 IndexedDB 里的 `projectIndex`（meta），因为 `seedSample`
的两个判据读的都是 meta —— 这样测的是真实决策路径，不用伪造一份旧工程本体。

音频功能本身另有 `scripts/audio-check.mjs`（30 项，见 [09-audio.md](09-audio.md)）。

跑法：

```bash
npm run dev            # 另开一个终端，5273 端口
node scripts/sample-check.mjs
```

脚本只清 IndexedDB、不清 localStorage —— 语言偏好留着，结果才不会随
headless 浏览器的 `navigator.language` 漂移。
