# 第一次打开：示例工程与介绍动画

一个空的工作台会让新用户卡在第一个问题上：**这玩意儿能做什么？**

所以第一次打开时，工程库里已经躺着一份做得差不多的示例，介绍页上还有一段
四拍动画把「画布 → 图层 → 关键帧 → 命令」走一遍。这一篇讲这两件事怎么落地、
以及为什么要这么落。

---

## 一、时序：谁在什么时候做

```
启动 → 路由 `/` → Launcher 挂载 → refresh()
                                    ├─ project.seedSample   ← 幂等：只写库，不动当前文档
                                    └─ project.listRecent   ← 读索引，渲染卡片
```

关键点：**塞示例是一个命令，不是 Launcher 直接写 IndexedDB**。

`Launcher` 的注释里写着「这里不碰 IndexedDB，也不改 store 里的 project」。这条规矩
在加示例时同样要守：所有写操作回命令总线，Launcher 只负责发命令与渲染。
好处是同一个动作在三种入口（页面、覆盖层、AI）里行为一致，且能在审计里看到。

`refresh()` 每次打开都会调 `project.seedSample`。这不会带来额外开销 ——
除了第一次，它都是一次 prefs 读就返回（见第四节）。

---

## 二、为什么不自动打开它

「自动加载并展示」有两种解法：自动跳进编辑器，或者放进工程库等用户点。

选了后者，理由是**第一屏该是可选的**：

| 自动打开 | 放进工程库 |
| --- | --- |
| 用户还没理解这是什么，就被塞进一个陌生画布 | 先看到工程库，知道「这里是我的东西」 |
| 想新建就得先关掉示例、再回来 | 想新建直接点左边 |
| 示例被编辑后，下次打开还是它 | 示例只是列表里的一条，随时可开可删 |

所以「自动加载」落在**数据层**（库里有这条记录），「展示」落在**列表层**（卡片 + 引导条），
不越界到导航层。

---

## 三、示例工程的三条约束

`src/core/sampleProject.ts` 里的注释写了详细理由，这里只列结论：

### 1. 零外部资源

没有图片、没有视频、不用本地字体。否则第一次打开就是一片「图片资源缺失」的灰块 ——
示例会变成故障演示。自检里有一条 `不依赖任何外部资源：assets === 0` 守着它。

### 2. 第 0 帧就是完整海报

这是最容易翻车的一条。`createDemoProject()` 的图层带着入场预设（`enter`），
而入场动画在 t=0 的透明度是 0 —— 照搬的话，新用户打开只看到背景和几条流线，
一个字都没有，还得先按空格播放才知道有内容。

打开工程时 `playhead` 恒为 0，所以示例**不用入场/退场预设**，只用关键帧轨道，
且轨道的第一个关键帧就是「设计位置」：

```ts
// 主标题：从下往上归位，起点比设计位置低 28px
title.animation.tracks = [track('y', [
  { time: 0, value: title.y + 28, kind: 'ease-out-cubic' },
  { time: 1400, value: title.y, kind: 'ease-out' },
])];
```

顺带解决了缩略图：`makeThumbnail` 在 t=0 渲染，有入场动画的话卡片上会是一张空图。

### 3. 看得出能改

- 时间轴上要有轨道 → 三条：主标题 `y`、眉标 `letterSpacing`（文本专有属性）、光斑 `rotation`
- 画布上要有一行提示 → 底层多一个 `试试看（可删除）` 文字层：`空格播放 · 拖动图层改位置 · 双击文字改字`
- 图层名要写人话 → `主标题` / `眉标` / `光斑 · 代码层`，图层面板本身就是说明书

主体复用 `createDemoProject()`：那份海报的设计已经调好了，没必要再画一遍。
差别只在 id、动画形态和多出来的一行提示。

## 四、幂等：两个判据，一条后路

```ts
if (!force && await hasSeededSample()) return { created: false, reason: 'seeded' };
const existing = await getProjectMeta(SAMPLE_PROJECT_ID);
if (existing && !force) { await markSampleSeeded(); return { created: false, reason: 'exists' }; }
```

两个判据分工不同：

| 判据 | 挡住什么 |
| --- | --- |
| prefs 里的 `sampleSeeded` | 99% 的情况，一次读就结束，不碰工程本体 |
| 固定 id `prj_sample_start` | 标记丢了但工程还在（手动清过 prefs、标记那次写失败） |

**记的是「已经塞过」，不是「用户没见过」。** 用户第一件事可能就是把它删掉 ——
那就该真的没了，而不是下次刷新又冒出来。

但删掉之后总得有条路放回来，所以空状态里有一个「放回示例工程」按钮，
走的是 `project.seedSample { force: true }`。`force` 存在就是为了这条后路。

### 为什么示例的 `version` 保持 1

`flushCurrent()` 里有一条：`version <= 1` 的工程切走时不落盘 —— 那是给「启动时内存里
那份演示工程」用的，否则每次刷新都会往库里塞一条新记录。

示例是**已经开始归档的记录**，不依赖这条豁免；保持 `version: 1` 只是表明
「建出来之后还没被任何命令改过」。用户打开它之后，`project.open` 会把它写成
`draft.version + 1`，之后自动保存就正常工作了。

## 五、介绍页那段动画

`src/ui/IntroDemo.tsx`，四拍循环，每拍 2.2 秒：

| 拍 | 画面 | 讲什么 |
| --- | --- | --- |
| 01 画布 | 舞台点亮，标题浮现 | 尺寸 · 时长 · 帧率 |
| 02 图层 | 标题框选中，图层面板对应行亮起 | 位置 · 样式 · 叠放 |
| 03 关键帧 | 播放头从左扫到右，菱形亮起，标题上抬、光斑放大 | 轨道 + 播放头求值 |
| 04 命令 | 命令行打字机式打出 `layer.create {...}`，画布上多一条 | 同一条命令总线 |

### 为什么不用 canvas 真渲染一套

介绍页要讲清楚的是**界面语言**（怎么选、怎么改、怎么打点），不是渲染效果。
用界面本身去画界面最直白；再挂一条渲染管线既慢，又等于在介绍「渲染」而不是「怎么用」。

真正的渲染能力由旁边的示例卡片承担 —— 那张缩略图就是渲染器的产物。

### 缩放：固定设计稿 + 等比缩放

内部是「百分比定位 + 固定像素细节」的混排。直接把容器拉大，方块会变长、字号不变，
比例全乱。所以先按 380×210 画一张，再用 `ResizeObserver` 量容器宽度做 `scale()`：

```tsx
const fit = () => setScale(el.clientWidth / DESIGN_W);
```

任何宽度下比例一致，窄屏也不会挤压。

### prefers-reduced-motion

检测到用户要求减少动态时，**停在第三拍**（信息量最大的一帧）且不循环。
这不是「关掉动画」，是「给一个静态但完整的说明图」。

## 六、故意没做的

- **自动跳进编辑器**：见第二节，第一屏该是可选的。
- **示例跟工程包一起走**：不进 `.kly`。它是本机的引导素材，不是用户数据。
- **多个示例 / 模板市场**：一个够了。要更多模板是另一个产品决策（分类、预览、来源标注）。
- **动画做成视频**：一段 20KB 的 CSS/SVG 比 2MB 的 mp4 更省，也不会有首帧黑屏。
- **把动画做成可交互**：介绍页的职责是「说明」，交互留给示例工程本身。

## 七、自检

`scripts/sample-check.mjs`，28 项，七个区块：

| 区块 | 验什么 |
| --- | --- |
| 首屏 | 一条示例、缩略图非空、带「示例」徽标、引导条说出内容规模 |
| 介绍动画 | 四拍齐全、相位会自己推进、指示器跟着走 |
| 减少动态 | `prefers-reduced-motion: reduce` 下停在第三拍且不动 |
| 幂等 | 刷新不重复创建、引导条只出现一次 |
| 打开它 | 8 层 / 3 条轨道 / 0 资源 / 无入场预设 / 画布真的渲染出内容 |
| 删除 | 删完清空、刷新不复活、空状态能一键放回 |
| 双语 | 英文模式下介绍区零中文、四拍标签也翻译了 |

跑法：

```bash
npm run dev            # 另开一个终端，5273 端口
node scripts/sample-check.mjs
```

脚本只清 IndexedDB、不清 localStorage —— 语言偏好留着，结果才不会随
headless 浏览器的 `navigator.language` 漂移。
